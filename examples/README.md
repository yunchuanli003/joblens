# 示例数据

不装扩展、不打开招聘网站，也能先看清这个工具到底输出什么。

这里的每一份结果都是 `src/core.js` **真实跑出来的**，不是手写的样例。

## 文件

| 文件 | 是什么 |
|---|---|
| `profile.sample.json` | 输入：一份虚构求职画像。字段与设置页「求职画像」一一对应，可以直接对照着填自己的 |
| `jobs.sample.json` | 输入：8 个虚构岗位卡片。字段结构对齐 `src/extract.js` 从页面抽出来的卡片对象 |
| `report.sample.md` | 输出：报告文本。面板上点「报告」复制出来的就是这种格式，可粘进笔记 |
| `report.sample.json` | 输出：同一份结果的机器可读形态，含每个岗位的 `verdict / score / reasons` |

## 这份数据演示了什么

8 个岗位刻意覆盖了不同的判定路径，顺序与 `report.sample.md` 一致：

| 结果 | 岗位 | 触发原因 |
|---|---|---|
| 92 推荐 | 嵌入式软件工程师 · 星野电子 | 标题命中「嵌入式」，标签命中 STM32、电路调试，岗位名对得上 |
| 87 推荐 | 硬件测试工程师 · 云栖智造 | 标题命中「硬件测试」，标签命中 DQA |
| 87 推荐 | 嵌入式硬件工程师 · 星野电子 | 标题命中「嵌入式」，标签命中 STM32 |
| 50 待看 | 硬件工程师 · 澜图仪器 | 标题方向对，但技能词一个没命中，落在 42–61 区间 |
| 30 跳过 | 用户增长运营 · 云栖智造 | 标题不含目标岗位名，分数被封顶后仍低于待看线 |
| 0 跳过 | 高级硬件工程师 · 恒川科技 | 城市不符（深圳，画像只收杭州、宁波）——硬门槛，直接归零 |
| 0 跳过 | 硬件测试员 · 恒川科技 | 正文命中排除词「外包派遣」 |
| 0 跳过 | 电子工程师 · 泊岸智控 | HR 半年前活跃，超过 14 天门槛 |

「0 分」不是没算，是硬门槛先命中、不进打分环节 —— 理由写在 `reasons` 里。

## 怎么来的

```bash
npm run sample         # 重新生成上面两个输出文件
npm run sample:check   # 重新算一遍并逐字节比对，不一致就退出码 1
```

`sample:check` 在 CI 里跑。所以「示例和代码输出不一致」这件事不需要人盯：**规则改了、示例忘了更新，CI 直接红**。

生成过程是确定性的：不读系统时间、不用随机数，页面时间取自 `jobs.sample.json` 的 `captured_at`。同一份输入永远得到同一份输出，否则这条检查会被时间戳漂移逼到关掉。

阈值不在这里复制一份，直接取 `src/core.js` 的 `DEFAULTS`。示例里写死 62 分线，迟早会和真源长出两个版本。

## 想改成自己的

1. 改 `jobs.sample.json` 的岗位或 `profile.sample.json` 的画像
2. 跑 `npm run sample`
3. 看 `report.sample.md`

注意：改完之后 `npm run sample:check` 会失败——这是预期行为，它只保证「仓库里提交的示例」与代码一致。要么接受这次改动一起提交，要么把两个输入文件还原。

## 声明

**公司名、岗位、薪资、HR 活跃状态全部虚构**，与任何真实企业或在招岗位无关。示例画像同样是虚构的，不代表仓库作者本人的求职意向。

示例的页面 URL 只作为报告里的一个字段出现，仓库不包含任何平台的源代码、接口文档、界面素材或真实抓取数据。
